# Request rules

A request has four fields: municipality name, project title, short description, and Budget attached.

Before it can be marked Reviewed:

1. Municipality name must be filled in.
2. Project title must be filled in.
3. Budget attached must be checked.

A name or title containing only spaces counts as empty. Description is optional. The budget checkbox records whether a budget is attached; there is no document upload feature.

You may save incomplete information as a draft. The server checks whether it is ready to review.

There are only two saved statuses: **New** and **Reviewed**. “Ready to review” and “Information missing” describe the check result; they are not extra statuses. Once Reviewed, the request cannot be edited.

All requests and rules are fictional. No other business rules are needed.

## Product UI

Treat Request Workbench as a real business application. User-facing UI must never mention the hackathon, workshop, training case, exercises, tasks, build sessions, checkpoints, demos, participants, Codex, or implementation instructions. This applies to headings, page titles, labels, help text, empty/loading/error states, footers, accessibility text, and activity data. Use business language only. Keep all learning instructions in the accompanying documentation, outside the application UI.
